# 5. Database Schema

The DDL is **generated** from `database/model/catalog.dsl` by `tools/schema_gen.py` and committed to
`database/schema/`. CI fails if the generated files drift from the catalog (`--check`) or if the DDL does not
apply to PostgreSQL 16 or the integrity tests fail.

## 5.3 Standard column contract

Every business table has:

```sql
id uuid PRIMARY KEY,                -- UUIDv7 generated by the app (time-ordered → B-tree friendly)
tenant_id uuid NOT NULL,            -- RLS boundary
[site_id uuid NOT NULL]             -- S-flag: ABAC scope
... domain columns ...
[workflow_instance_id uuid, workflow_state varchar(50)]  -- W-flag
[current_version_no integer]                             -- V-flag
ext jsonb NOT NULL DEFAULT '{}',    -- configured fields (Field Builder)
row_version integer NOT NULL,       -- optimistic concurrency (enforced by trigger)
created_at, created_by, updated_at, updated_by
```

## 5.4 Triggers per table (generated)

| Trigger | Applies to | Behaviour | Proven by |
|---|---|---|---|
| `trg_touch` | all | Enforces `row_version` match (else `serialization_failure`), bumps it, stamps `updated_*`, forbids changing `tenant_id`/`created_*` | OQ-DI-003, 004 |
| `trg_audit` | GxP tables (not `N`) | Writes field-level diff to `audit.audit_trail`. **Rejects the write if no authenticated actor is in session context** | OQ-DI-001, 002, 003 |
| `trg_no_delete` | GxP tables | Blocks physical DELETE | OQ-DI-005 |
| `trg_append_only` | signatures, history, inventory transactions, parameter values, version tables, etc. | Blocks UPDATE | OQ-DI-008 |
| `trg_protect_audit` | `audit.audit_trail` | Blocks UPDATE/DELETE even for owner/superuser paths | OQ-DI-007 |
| RLS `tenant_isolation` | all | `USING` + `WITH CHECK` on `tenant_id = app.tenant_id` | OQ-DI-006 |

Tamper evidence below the application layer (for example a DBA disabling triggers) is detected by
`audit.verify_seals()` (OQ-DI-009). The sealer job runs every 5 minutes and seals the latest range. Each seal
chains the previous seal hash and can be signed with a KMS asymmetric key (`kms_signature`).

## 5.5 Session context contract

The .NET `GxpDbConnectionInterceptor` runs at the start of every transaction:

```sql
SELECT set_config('app.tenant_id',      @tenant,  true),
       set_config('app.user_id',        @user,    true),
       set_config('app.user_display',   @display, true),
       set_config('app.on_behalf_of',   @obo,     true),
       set_config('app.change_reason',  @reason,  true),
       set_config('app.correlation_id', @corr,    true),
       set_config('app.client',         @client,  true);
```

`is_local = true` scopes the settings to the transaction, so a pooled connection (PgBouncer in transaction mode)
cannot leak identity between requests.

## 5.6 Index strategy (generated, then tuned)

| Index | Rule |
|---|---|
| `(tenant_id)` | every table |
| `(tenant_id, site_id)` | S-flag tables |
| FK column | every FK (avoids lock escalation on parent update and supports joins) |
| `UNIQUE (tenant_id, code)` | every `*` column (business keys such as `deviation_no`, `batch_no`, `lot_no`) |
| trigram GIN on business keys | fast "type-ahead" lookups of record numbers |
| `(tenant_id, status)` | tables with `status` (work queues) |
| `(tenant_id, due_date / next_review_date / expiry_date)` | overdue dashboards, FEFO |
| `(tenant_id, workflow_state)` + GIN `ext jsonb_path_ops` | workflow-enabled tables (configured-field filtering) |
| Audit: `(tenant, schema, table, record, occurred_at)`, `(tenant, actor, occurred_at)`, BRIN `(occurred_at)` | record history, user activity, time scans |

Generated indexes are the floor. Query-specific composite and partial indexes (for example
`WHERE status NOT IN ('CLOSED','CANCELLED')`) are added in hand-written migrations under
`database/migrations/` after load testing.

## 5.7 Partitioning and volume

| Table | Strategy |
|---|---|
| `audit.audit_trail` | RANGE monthly by `occurred_at`. Old partitions are detached → exported to Parquet + PDF/A summary in WORM storage → kept attached read-only until the retention review |
| `mes.process_data_point` | High-frequency time series. **Recommend TimescaleDB hypertable or an external historian.** Only CPP values that land on the batch record go to `mes.batch_parameter_value` |
| `wms.inventory_transaction` | RANGE yearly once volume exceeds about 100 M rows |
| `notif.notification`, `intg.outbox_message`, `intg.inbox_message` | Purged (non-GxP, `N` flag) |

## 5.8 Configured fields (`ext`) design

- Definitions live in `meta.field_definition` (versioned). `storage = 'EXT'` means the value is stored in `ext`.
  `storage = 'COLUMN'` is reserved for platform-shipped fields.
- On write, `PharmaOS.Metadata.Client` validates `ext` against the JSON Schema compiled from the active field
  definitions (type, required, regex, lookup membership, range).
- Configured fields are audited automatically because `ext` diffs show up in `changed_fields = {ext}`. The audit
  UI expands the JSON diff to field level using the field labels in force at the time of the change, which come
  from `meta.field_definition_version`.
- Promoting a configured field to a real column (for performance) is a platform migration. It is never done per
  tenant.

## 5.9 Regenerating and extending

1. Edit `catalog.dsl`. For example, to add a table to `qms`:
   `nonconformance W S | nc_no:c!*, title:l!, owner_id:>iam.app_user!, status:st!`
2. Run `python3 tools/schema_gen.py`. The DDL, ERD, and dictionary update together.
3. For a **deployed** database, write an expand/contract migration in `database/migrations/` (EF Core or
   Flyway-style). The generated DDL is the target state; migrations are the path to it. A CI job diffs a migrated
   database against a fresh-from-DDL database (`migra` or `pg_dump --schema-only` compare) and fails on any
   difference.
